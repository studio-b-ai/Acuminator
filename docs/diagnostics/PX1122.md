# PX1122
This document describes the PX1122 diagnostic.

## Summary

| Code   | Short Description                                                                                                                                                                                                                                | Type    | Code Fix    |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- | ----------- |
| PX1122 | A `PXDatabase.Execute` call uses an `INSERT INTO RolesIn[Graph|Member|Cache] SELECT ... FROM RolesIn...` pattern that silently null-ops when the source `ScreenID` has zero rows. Add a pre-COUNT check on the source plus a `Rolename='*'` fallback. | Warning | Unavailable |

## Diagnostic Description

Acumatica customization plugins (classes derived from `Customization.CustomizationPlugin`) grant screen-level role access by copying rows from a source (template) ScreenID in the `RolesInGraph`, `RolesInMember`, and `RolesInCache` tables:

```sql
INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
SELECT @target, Rolename, ApplicationName, AccessRights
FROM RolesInGraph
WHERE ScreenID = '<source_template_screen>'
```

If the source template ScreenID has zero rows in the target tenant, the `INSERT … SELECT` produces zero rows — it null-ops silently with no error.  The intended grant for the new screen never lands.  The new screen is then inaccessible: Acumatica's OData endpoint returns HTTP 404 and the screen does not appear in the access-rights tree in the UI.

The PX1122 diagnostic inspects calls to `PXDatabase.Execute` and reports a warning when:
1. The SQL argument contains an `INSERT INTO RolesIn[Graph|Member|Cache] SELECT ... FROM RolesIn...` pattern, **and**
2. The enclosing method body does **not** contain both:
   - A pre-COUNT check (`COUNT(` or `COUNT_BIG(`) to verify the source has rows, **and**
   - A `Rolename='*'` direct-write fallback for when the source count is zero.

The check is per-call: each unguarded `INSERT … SELECT` in the same `PXDatabase.Execute` call is reported independently.  Comments (`--` line and `/* */` block) and string literals (`'...'`) inside the SQL are stripped before analysis, so keywords that happen to appear inside them do not produce false positives or false negatives.

## Example of Incorrect Code

### Basic anti-pattern — no guard, no fallback

```C#
using PX.Data;
using Customization;

public class MyPlugin : CustomizationPlugin
{
    public override void UpdateDatabase()
    {
        // Warning PX1122: if SB501000 has zero RolesInGraph rows in this tenant,
        // the new screen SB302000 silently receives no role grant.
        PXDatabase.Execute(@"
            INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
            SELECT 'SB302000', Rolename, ApplicationName, AccessRights
            FROM RolesInGraph
            WHERE ScreenID = 'SB501000'
        ");
    }
}
```

### All three RolesIn* tables, all three unguarded

```C#
PXDatabase.Execute(@"
    INSERT INTO RolesInGraph  (ScreenID, Rolename, ApplicationName, AccessRights)
    SELECT 'SB302000', Rolename, ApplicationName, AccessRights
    FROM RolesInGraph WHERE ScreenID = 'SB501000';

    INSERT INTO RolesInMember (ScreenID, Rolename, ApplicationName, Cachetype)
    SELECT 'SB302000', Rolename, ApplicationName, Cachetype
    FROM RolesInMember WHERE ScreenID = 'SB501000';

    INSERT INTO RolesInCache  (ScreenID, Rolename, ApplicationName, Cachetype)
    SELECT 'SB302000', Rolename, ApplicationName, Cachetype
    FROM RolesInCache  WHERE ScreenID = 'SB501000'
");
// Warning PX1122: all three copies are unguarded.
```

### Count check present but no Rolename='*' fallback

```C#
public override void UpdateDatabase()
{
    int count = 0;
    PXDatabase.Execute(@"SELECT COUNT(*) FROM RolesInGraph WHERE ScreenID = 'SB501000'");

    // Warning PX1122: COUNT check exists but there is no Rolename='*' fallback write.
    PXDatabase.Execute(@"
        INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
        SELECT 'SB302000', Rolename, ApplicationName, AccessRights
        FROM RolesInGraph WHERE ScreenID = 'SB501000'
    ");
}
```

## Example of Correct Code

### Pre-COUNT check + Rolename='*' fallback in the same method

```C#
public override void UpdateDatabase()
{
    // 1. Count the source rows.
    int sourceCount = 0;
    PXDatabase.Execute(@"
        SELECT @count = COUNT(*) FROM RolesInGraph WHERE ScreenID = 'SB501000'
    ");

    if (sourceCount > 0)
    {
        // 2a. Source has rows — copy them.
        PXDatabase.Execute(@"
            INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
            SELECT 'SB302000', Rolename, ApplicationName, AccessRights
            FROM RolesInGraph WHERE ScreenID = 'SB501000'
        ");
    }
    else
    {
        // 2b. Source is empty — write a direct Rolename='*' grant.
        PXDatabase.Execute(@"
            INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
            VALUES ('SB302000', '*', '/', 4)
        ");
    }
}
```

### Inline COUNT + conditional fallback with Rolename='*'

```C#
public override void UpdateDatabase()
{
    PXDatabase.Execute(@"
        DECLARE @cnt INT;
        SELECT @cnt = COUNT(*) FROM RolesInGraph WHERE ScreenID = 'SB501000';

        IF @cnt > 0
            INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
            SELECT 'SB302000', Rolename, ApplicationName, AccessRights
            FROM   RolesInGraph WHERE ScreenID = 'SB501000';
        ELSE
            INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
            VALUES ('SB302000', '*', '/', 4);
    ");
}
```

### Shared helper referenced from UpdateDatabase

If the pre-COUNT check and the `Rolename='*'` fallback live in a shared helper method (see *Heuristic Limitations* below), suppress the diagnostic:

```C#
public override void UpdateDatabase()
{
    // Acuminator disable once PX1122 — guard + fallback are in EnsureScreenRights helper.
    PXDatabase.Execute(@"
        INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
        SELECT 'SB302000', Rolename, ApplicationName, AccessRights
        FROM RolesInGraph WHERE ScreenID = 'SB501000'
    ");
}
```

## Suppression

If a specific call is intentionally unguarded, or the guard logic lives outside the immediate method body, suppress the diagnostic with an Acuminator comment:

```C#
// Acuminator disable once PX1122 — one-time migration; source template is guaranteed non-empty in this tenant.
PXDatabase.Execute(@"
    INSERT INTO RolesInGraph (ScreenID, Rolename, ApplicationName, AccessRights)
    SELECT 'SB302000', Rolename, ApplicationName, AccessRights
    FROM RolesInGraph WHERE ScreenID = 'SB501000'
");
```

Or use a suppression file when Acuminator is installed as a VSIX extension.

## Heuristic Limitations

The diagnostic is regex-based and does not perform a full T-SQL parse.  The following patterns are known limitations:

- **Fallback in a separate helper method.** If the `COUNT(` check or the `Rolename='*'` write is implemented in a helper method that is called from the same method body, PX1122 may report a false positive because the heuristic only scans string literals within the immediately enclosing `MethodDeclarationSyntax`.  Suppress with an Acuminator comment for this pattern.
- **Dynamic SQL built at runtime** (for example, `StringBuilder`-composed SQL with non-constant fragments) cannot be analyzed statically; PX1122 silently skips these calls.
- **Interpolation holes that stand in for SQL keywords** (for example, `$"INSERT INTO {tableName} SELECT ..."`) are not modeled.

These edge cases are documented rather than fixed because the heuristic catches the canonical anti-patterns at near-zero false-positive cost.
